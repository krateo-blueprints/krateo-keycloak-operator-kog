# keycloak-config-kog

Krateo Operator Generator (KOG) packaging that turns **Keycloak Admin API resources
into native Kubernetes custom resources**.

## What is this

`kubectl apply` a `KeycloakClient` (or realm, group, mapper, identity provider,
authentication flow, …) and KOG's
[`oasgen-provider`](https://github.com/krateo-platformops/oasgen-provider) and
[`rest-dynamic-controller`](https://github.com/krateo-platformops/rest-dynamic-controller)
reconcile it against a running Keycloak's Admin REST API — no plugin, no operator code
for the CRUD path.

This is the **configuration** half of the Keycloak↔Krateo↔OpenStack SSO work. The
**lifecycle** half (installing Keycloak itself) is the sibling
[`krateo-keycloak-blueprint`](https://github.com/krateo-blueprints/krateo-keycloak-blueprint),
which wraps the official Keycloak Operator. They connect at one point: the bearer
`keycloak-admin-token` Secret this KOG uses to call the server the blueprint stands up.

Two design decisions define it:

1. **`securitySchemes` patched into every OAS asset.** Keycloak's published OAS omits
   a security scheme; KOG only accepts `http/bearer`. Every asset declares `bearer`, so
   oasgen-provider generates the paired `<Kind>Configuration` CRD carrying the auth
   block. The Admin API is genuinely Bearer, so no auth-bridge proxy is needed.
2. **Short-lived admin token via External Secrets Operator.** Keycloak admin tokens
   live only minutes, so `templates/externalsecret.yaml` has ESO mint a fresh one from
   Keycloak's token endpoint (`client_credentials`) into the `keycloak-admin-token`
   Secret on a sub-TTL interval.

Resources exposed (all under `keycloak.ogen.krateo.io/v1alpha1`): `KeycloakRealm`,
`KeycloakClient`, `KeycloakProtocolMapper`, `KeycloakClientScope`, `KeycloakGroup`,
`KeycloakUser`, `KeycloakIdentityProvider`, `KeycloakIdentityProviderMapper`,
`KeycloakAuthenticationFlow`, `KeycloakRequiredAction`, and
`KeycloakAuthenticationExecution` (whose lifecycle is delegated to Snowplow
`RESTAction`s). See [docs/overview.md](docs/overview.md) and
[docs/api.md](docs/api.md).

## Install

```bash
helm install oasgen-provider krateo/oasgen-provider -n krateo-system --create-namespace

# Pre-create the service-account client secret ESO uses to mint admin tokens
# (the Secret must carry the ESO webhook label):
kubectl -n krateo-system create secret generic keycloak-kog-client \
  --from-literal=clientSecret='<krateo-kog client secret>'
kubectl -n krateo-system label secret keycloak-kog-client external-secrets.io/type=webhook

helm install keycloak-config-kog ./chart -n krateo-system \
  --set keycloak.baseUrl=https://<KEYCLOAK_HOST>

kubectl apply -f samples/00-configurations.yaml
kubectl apply -f samples/10-sso-realm.yaml
kubectl -n krateo-system get keycloakclients.keycloak.ogen.krateo.io -w
```

Or install as a Krateo Composition (`compositiondefinition.yaml` +
`examples/composition.yaml`). Full steps and prerequisites are in
[docs/usage.md](docs/usage.md).

## Configure

Everything is `chart/values.yaml`, typed by `chart/values.schema.json`. The top-level
keys are `keycloak` (the target `baseUrl`), `auth` (the ESO-minted admin token),
`restDefinitions` (which resource CRDs to emit — each `enabled` by default),
`snowplow` (delegation for `KeycloakAuthenticationExecution`), `resourceGroup`, and
`verbose`. The full surface is documented in
[docs/configuration.md](docs/configuration.md).

## Develop & release

`chart/assets/*.yaml` are generated by `hack/gen_oas_assets.py` from the field lists
curated there — edit that script and re-run it to change the exposed field surface.

CI runs on every PR and push to `main`:

- **`chart-tests.yaml`** — `helm lint` + `helm template`, an OAS-parse check, and the
  offline `KeycloakAuthenticationExecution` delegation-wiring tests
  (`tests/delegation`).
- **`lint.yaml`** — the shared Krateo docs-standard linter (`lint-docs`).

Release by pushing a SemVer git tag matching `chart/Chart.yaml`'s `version`;
`release-chart.yaml` publishes the chart to
`oci://ghcr.io/krateo-blueprints/charts/keycloak-config-kog`, then bump
`compositiondefinition.yaml`'s `spec.chart.version`. Details in
[docs/release.md](docs/release.md).
